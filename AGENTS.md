## Learned User Preferences

- This is a public crate. Do not name the private dogfood app, its path, its UI copy, or its project and context keys in committed files.
- Do not use UniFFI. Keep the thin in-crate Kotlin host on Android and the Swift host on iOS.
- The Android Kotlin host stays in this crate. Consuming apps should not copy a host or a custom MainActivity; Dioxus CLI 0.7+ bundles it.
- No Maestro, and no native test harness (Gradle, Xcode, JNI, C ABI). Cover library behavior with idiomatic Rust tests (`rstest` and `cargo test` on the mobile targets). The only app is `example/`, a `dx` project that depends on the crate by path and is the working folder for experiments and the live check.
- The library owns Qonversion primitives, typed errors, and the hosts. The app owns the project key, user ids, payload field names, localized UI, store-open intents, and fail-open vs fail-closed.
- Play billing disconnected is `QonversionError::StoreUnavailable` returned before the No-Codes UI opens. Do not treat `loadScreen` as that check, and do not ship a dialog or a Play Store intent here.
- Scope stays iOS and Android. Do not add web or desktop support.
- After a feature lands, the user expects a simplify pass on the diff before it is treated as done.
- This crate is a library for other projects. Code that stays reachable on a platform needs tests on that platform under the same cfg. Do not widen a cfg such as `test` just to compile it elsewhere, and do not delete its coverage to silence warnings.
- The live-test project key comes from a gitignored `example/.env` with `example/.env.example` committed, and an exported `QONVERSION_PROJECT_KEY` wins. Keep test setup out of the published root crate: no root `build.rs`, root `.env`, or root dev-dependencies for it.
- Keep the live check lean: no log-redaction scripts or extra test runners. The key is the client SDK Project Key, not the `sk_` Secret Key, and GitHub masks secrets.

## Learned Workspace Facts

- The Rust API depends on `dioxus-lib` 0.6. The Android host at `android/src/main/kotlin/io/dioxus/qonversion/DioxusQonversionHost.kt` is auto-bundled by Dioxus CLI 0.7+ via manganis. The non-`dx` fallback is to compile that Kotlin file into the app and add `io.qonversion:no-codes:1.8.0`.
- Load `DioxusQonversionHost` only with `Context.getClassLoader().loadClass`. `Env::find_class` is for framework classes such as `Looper` and `Activity`. `FindClass` from the JNI worker thread cannot see the app class and can panic `jni` 0.22 on release if a pending exception is left.
- Android `showScreen` and init completion run on the main looper. Call `show_screen` from Dioxus `spawn` so the billing preflight can wait without deadlocking the UI thread.
- GitHub Actions `test.yml` reuses `cargo-test.yml`: iOS `cargo test` on `aarch64-apple-ios-sim` (booted simulator, macOS) and Android `cargo test` via cross on `aarch64-linux-android`. There is no extra host-only Ubuntu job.
- Qonversion SDK behavior comes from `docs/qonversion/llms.txt` and the matching docs pages. The Qonversion MCP is for live project data, not a substitute for those docs.
- Linear sync for this repo uses the `dioxus-qonversion` workspace.
- `cargo test` and `cross test` cannot reach the real Qonversion SDK. They run outside an app process, with no `ndk_context` and no SDK on the classpath, so `initialize` returns `HostMissing` on mobile and `UnsupportedPlatform` on the host. Only an app built by `dx` can call the SDK.
- The live check runs `example/` with `dx run` from the `#[ignore]`d `rstest` cases in `example/tests/remote_config.rs`: from `example/`, `cargo test -- --ignored --nocapture android|ios` on a booted x86_64 emulator or `aarch64-apple-ios-sim` simulator. `example/build.rs` compiles in `QONVERSION_PROJECT_KEY`, `QONVERSION_REMOTE_CONFIG_CONTEXT_KEY`, and `QONVERSION_NO_CODE_CONTEXT_KEY` (env first, then `example/.env`). The test pins only the Remote Config context key. The No-Codes key comes from the environment or `example/.env`, and CI passes it as the `QONVERSION_NO_CODE_CONTEXT_KEY` secret. The app prints one `QONVERSION_E2E {json}` line, which reaches `dx` on Android through tao's `RustStdoutStderr` logcat tag. The ignored tests `remote_config` and `no_code` share one `dx` run per platform. `remote_config` asserts a non-empty `payload` object. `no_code` asserts a non-empty `screen_id` from `load_screen`. Each prints a one-line summary without the payload or screen id. `show_screen` stays the manual demo button. Keep dashboard field names and values out of the public repo. `.github/workflows/remote-config-e2e.yml` (Live SDK check) runs both cases as a matrix (API 34 emulator, macOS simulator). A manual run takes the client project key and the No-Codes context key as workflow inputs; a blank input uses the `test` environment secret, and a typed input is visible on the run page.
- Dioxus CLI 0.7 `--device` on Android fuzzy-matches the adb serial from `adb devices -l` (such as `emulator-<port>`), not the AVD name. Without `--device`, dx boots the first AVD even when an emulator is already running. With `--device` and no `--target`, dx probes `adb shell uname -m` without `-s` and falls back to aarch64 when that fails, so pass `--target x86_64-linux-android` for the x86_64 emulator.
- The agent sandbox blocks `api.qonversion.io`, so run the live Remote Config check, and any emulator it uses, outside the sandbox.
- `src/screen.rs` is the shared screen core. Its `extern "C"` callbacks `dioxus_qonversion_notify_screen_failed` and `dioxus_qonversion_notify_screen_event` are `#[cfg(target_os = "ios")]` for the Swift host and are tested in `screen::tests::c_abi` under the same cfg. Android reaches the same handlers through JNI methods registered in `src/native/android.rs`.
- Deferred purchases (Ask to Buy and Play pending) are delivered to `set_entitlements_updated_handler` with the same entitlements envelope as `check_entitlements`. Both hosts register the listener during init and forward only a successful purchase result. The Swift host retains the listener because Qonversion holds it weakly. Delivery is off the native main thread; malformed JSON is logged and dropped. The iOS callback `dioxus_qonversion_notify_entitlements` is `#[cfg(target_os = "ios")]`; Android calls JNI `notifyEntitlementsUpdated`.
